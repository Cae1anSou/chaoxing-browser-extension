# chaoxing-browser-extension

[![CI](https://github.com/Cae1anSou/chaoxing-browser-extension/actions/workflows/ci.yml/badge.svg)](https://github.com/Cae1anSou/chaoxing-browser-extension/actions/workflows/ci.yml)

一个面向超星学习页面的浏览器插件，基于 Chrome Manifest V3 实现，提供鼠标移出事件拦截、已识别的反调试处理，以及基于逐题反馈的手动和自动答案枚举功能。

当前版本为 **0.5.0**。插件可以直接加载，无需构建，也不需要部署后端服务。

## 项目目的

**本项目以学习、研究和技术交流为目的开发。** 开源的目的是交流浏览器扩展开发、页面事件传播、JavaScript 反调试机制，以及基于页面反馈的状态管理与自动化实现。项目源码采用 [MIT 许可证](LICENSE) 发布。

请仅在本人有权操作且获得允许的测试环境中开展实验，遵守所在学校、课程和平台的相关规定。请勿将本项目用于考试作弊、代刷课程、伪造学习记录或其他未经授权的行为。本项目与超星官方无关联，也不承诺课程完成、成绩提升或持续兼容平台。

## 功能介绍

### 鼠标移出事件拦截

插件在事件捕获阶段拦截没有目标元素的 `mouseout` 事件，用于研究播放器依赖鼠标离开事件暂停播放的行为。页面内部有明确目标元素的鼠标移动仍会放行。

这项处理没有删除播放器监听，但可能同时影响页面中其他依赖同类事件的功能。插件不修改学习时长上报或防多开逻辑。

### 已识别的反调试处理

插件会清除样本中已确认的反调试定时器，并拦截通过 `Function` 或 `Function.prototype.constructor` 创建、函数体仅包含 `debugger` 语句的动态函数，以便观察页面脚本的运行过程。

处理范围限定于已识别的模式。直接写在脚本中的 `debugger`、通过 `eval` 生成的代码，以及包含其他业务语句的函数体不在拦截范围内。插件不会删除整个业务脚本，也不会修改页面的内容安全策略（CSP）。

### 基于逐题反馈的答案枚举

在已适配的作业页面中，插件会显示“答案枚举研究”面板，读取页面返回的正确、错误、部分正确标记及对应作答内容，并在浏览器本地保存逐题进度。候选答案来自选项枚举，不依赖外部题库或 AI 服务。

目前支持单选题、判断题，以及最多 12 个选项的多选题。单选和判断逐个尝试候选。多选提供“反馈剪枝＋信息量优先”和“完整枚举”两种策略；已明确判定正确的答案都会锁定，手动与自动模式使用相同策略和进度。

快速策略基于已观察到的判分规则：完全正确返回正确，正确答案的非空真子集返回部分正确，包含任意错项返回错误。它会用所有历史反馈筛掉不可能的完整答案，再选择最坏情况下剩余可能答案最少的探测组合；并列时优先更均衡、且有机会直接正确的组合。例如 `CE` 部分正确且 `BCE` 错误时，可以推断 C、E 必选而 B 必须排除。推断出的唯一答案仍需实际提交并得到正确反馈才会锁定。

面板默认选择快速策略，使用前应确认本作业采用上述判分规则，其他作业不能仅凭课程相同就假定适用。逐题进度会显示剩余可能答案与规则推断。发现历史反馈无法共同满足该规则时，该题会撤销剪枝并回退完整枚举，不删除真实尝试记录；未出现矛盾不等于已经证明规则适用。也可以主动切换到完整枚举，切换不会丢弃已有反馈或正确答案。完整枚举不依赖部分正确的具体判分规则，只排除已经试过且未完全正确的组合。

在符合上述规则的确定性模拟中，遍历五个选项的全部 31 种非空正确答案，旧策略最坏需要 31 轮、均匀分布下平均 16 轮；新策略最坏需要 5 轮、平均约 4.16 轮。这是单题完整真值空间的测试结果，不是所有课程或题型的性能保证。

手动模式只填入下一轮候选，由使用者检查后通过原页面提交。自动模式会按轮次填入候选、点击原页面的提交按钮，并确认已识别的弹窗；页面重定向后继续读取反馈。**自动模式会产生真实的作业提交，并非仅在本地模拟。** 只有当前结果中的每道题都明确正确时，才会判定完成。

## 安装插件

### 下载源码

在 GitHub 仓库首页点击 **Code → Download ZIP**，下载后先解压。解压后的项目文件夹内应包含 `README.md` 和 [`extension/`](extension/)；`extension` 文件夹内应能看到 `manifest.json`。安装插件不需要 Node.js，也不用执行构建命令。

### 加载到 Chrome

使用 Chrome 111 或更新版本，在地址栏输入 `chrome://extensions` 并打开，开启右上角的“开发者模式”。点击“加载已解压的扩展程序”，选择刚解压出来的 **`extension` 文件夹**，也就是直接包含 `manifest.json` 的那一层；不要选择 ZIP 文件或整个项目根目录。

扩展列表中出现 **chaoxing-browser-extension**，且开关处于启用状态，就说明已加载。请保留这个本地文件夹，移动或删除它可能导致插件无法正常加载。

### 打开学习页面

安装后重新打开或刷新超星学习页面，让插件随页面加载。插件没有独立的弹出窗口，不需要点击工具栏图标启动；鼠标事件与反调试处理会在匹配页面中自动启用，作业研究面板则只会出现在已适配且能识别题目结构的作业页面中。

## 使用方式

### 查看面板与选择策略

在允许开展实验的作业页面中，题目上方会出现“答案枚举研究”面板。等待读取完成后，可以看到题目总数和已确认正确的数量，展开“查看逐题进度”可查看各题状态。鼠标事件与反调试处理不需要在此面板中另行开启。

开始前检查“多选策略”下拉框。默认的“反馈剪枝＋信息量优先”依赖前文所述判分规则；如果无法确认当前作业适用，请选择“完整枚举”。两种模式共用已有的反馈和正确答案，切换策略不会丢失进度。

### 手动填入与提交

点击“填入下一轮答案”，插件会保留已确认正确的答案，并为其他题目填入下一轮候选。检查题目选项后，再点击原页面的 Submit 或提交按钮，并按页面提示确认。**手动填入本身不会自动提交。**

页面返回新的判题结果后，面板会读取反馈并更新进度。仍有未解决的题目时，可以继续点击“填入下一轮答案”，重复检查和提交；如果面板提示停止，请先查看具体原因。

### 自动运行与停止

自动模式需要主动点击“自动枚举并提交，直到全部正确”启动。每轮提交前有 5 秒倒计时，默认本次最多提交 31 轮，可在启动前调整为 1～4095 的整数。达到轮数上限不代表已找到全部正确答案。

点击“停止自动模式”会取消倒计时和后续操作，已经发出的请求无法撤销。自动运行期间不能手动填入、切换策略或清空记录。停止后重新启动会重置本次轮数，但保留逐题进度；点击“清空本作业记录”则会从当前页面反馈重新建立记录，并保留当前选择的策略。

自动任务归属于启动它的标签页，通过浏览器 Web Locks 避免同一作业并发提交。重定向后会接续同一会话，其他标签页可以停止任务但不会自动接管。浏览器恢复标签页时可能继续原会话，需要取消时请先点击停止。没有 Web Locks 支持时，只能使用手动模式。

## 更新、停用与常见问题

更新时，先停止正在运行的自动任务，再下载并解压新版源码。在 `chrome://extensions` 中可通过扩展卡片的“详细信息”查看当前加载路径，将该路径下的插件文件替换为新版 `extension` 内的文件，点击扩展卡片上的重新加载按钮，然后刷新学习页面。

如果提示“找不到清单文件”，请确认选择的是直接包含 `manifest.json` 的 `extension` 文件夹。如果没有出现研究面板，先确认扩展已启用并刷新页面，再检查是否进入了已适配的作业页；课程首页、视频页不显示作业面板是正常现象。未适配页面的范围见下文。

如果出现 `Extension context invalidated`，说明旧标签页仍在使用失效的扩展环境，需要刷新。如果页面已暂停在 `debugger`，请关闭该学习标签页后重新打开，安装或更新插件不会解除已有的暂停状态。遇到验证码、未知弹窗或反馈异常时，请先处理页面问题，再决定是否重新启动自动模式。

需要停用时，先在面板中停止自动任务，再到 `chrome://extensions` 关闭插件开关并刷新学习页面；需要卸载则点击扩展卡片上的“移除”。

## 适配范围与限制

鼠标事件与反调试脚本匹配 HTTPS 下的 `mooc*.chaoxing.com` 页面及其符合注入规则的子 frame。作业面板匹配 `*.chaoxing.com/mooc-ans/work/doHomeWorkNew*` 路径，并依赖已适配的页面结构；平台更新后可能失效。

随机选项、未适配题型、题目变化、反馈冲突或候选耗尽会使相关操作停止。自动模式遇到缺少反馈、返回旧结果、验证码、未知弹窗、提交入口消失，或两分钟内没有完成重定向时，也会停止，不自动重试结果不明的提交。平台如果限制重答次数或提前结束作答，枚举可能无法完成。

插件通过原页面控件操作选项和提交，不自行拼接提交请求。枚举依赖平台返回足够的逐题反馈，也依赖平台允许继续作答，不保证适用于所有课程或作业。

## 权限与本地数据

插件仅声明 `storage` 权限，用于通过 `chrome.storage.local` 保存题目选项、作答反馈、已确认答案和自动会话状态。逐题记录按站点、账号、课程、班级、作业和答卷隔离；选项内容变化后，对应旧记录会失效。

插件不包含后台服务，不主动连接外部题库、统计或遥测服务，也不通过自身的网络请求上传这些记录。自动提交通过原页面控件触发，仍会由平台页面向平台服务器发送请求。

“清空本作业记录”只重建当前作业的进度，不清除其他作业的数据。请勿公开浏览器存储导出或包含个人信息的调试输出。

## 调试与开发

插件源码位于 [`extension/`](extension/)，测试位于 [`tests/`](tests/)。`main.js` 负责事件与反调试处理，`page-actions.js` 提供页面控件操作桥接，`quiz*.js` 负责题目读取、候选生成、本地进度和自动会话管理。修改源码后，重新加载扩展并刷新目标页面即可验证。

在开发者工具 Console 中选择对应 frame，执行以下代码可查看安装状态和拦截计数。不同 frame 的计数相互独立。

```javascript
window.__CX_RESEARCH__.status()
```

执行以下代码可停用当前 frame 的事件与反调试补丁，并恢复相关函数入口。已经清除的定时器和已经生成的空函数不会自动恢复；要完整恢复原页面行为，请在扩展管理页停用插件后刷新页面。作业自动任务请通过面板单独停止。

```javascript
window.__CX_RESEARCH__.disable()
```

安装 Node.js 后，可在仓库根目录运行本地测试：

```bash
node --test tests/*.test.cjs
```

测试覆盖鼠标事件拦截、反调试处理、页面控件桥接、候选枚举、正确答案锁定、反馈冲突及自动会话等逻辑，不执行真实作业提交。`tests/quiz-pruning.test.cjs` 遍历五选多选的所有非空真值，验证轮数、剪枝、唯一答案验证和规则矛盾回退。

GitHub Actions 的 [CI 工作流](.github/workflows/ci.yml) 会在推送和 Pull Request 时自动使用 Node.js 24 检查插件与测试脚本的 JavaScript 语法，并运行上述全部单元测试，无需安装第三方依赖。也可以在仓库的 Actions → CI 页面点击 Run workflow 手动运行。CI 不执行浏览器模拟或真实站点提交。

[`tests/browser-auto-fixture.js`](tests/browser-auto-fixture.js) 提供浏览器模拟场景，用于验证 DOM 操作、Web Locks 和 iframe 重建。模拟不代替真实扩展隔离环境中的 CSP 验证，也不代表已验证所有平台页面。
